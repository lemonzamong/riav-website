# 릴리스 보고서

릴리스 후보일: 2026-07-10  
상태: 구현·검증·운영 배포 완료

## 요약

Iruvy의 기존 한 페이지 정적 소개 사이트를 기관 구매자 중심의 9개 경로 프리미엄 홍보 사이트로 재구성함. 공개 이야기의 중심을 데이터 수집이나 미래 기술이 아니라 `복잡한 실내에서 실제 목적지까지 스스로 이동`하는 사용자 가치에 두고, 제품 경험·도입 과정·시설별 구매 이유·실증 근거·기술·문의 흐름을 분리함.

## 변경 전

- 한 페이지에 제품, 기술, 실증, 도입 모델이 혼재
- 비전 중심 첫 문구로 제품 이해가 늦음
- 이전 `Riav`, `Atmos` 이름이 제품 화면과 공유 이미지에 남음
- 기관 관심과 실제 도입이 혼동될 수 있는 표현
- 수치의 대상, 과제, 제한이 충분히 공개되지 않음
- 외부 글꼴 두 곳에 의존
- 문의가 이메일 주소 링크뿐임
- 자동 검사와 접근성 선언이 없음

## 변경 후

- 첫 화면에서 제품, 대상 공간, 안내 방식, 주요 행동을 즉시 설명
- 제품·솔루션·기술·실증·회사·문의·개인정보·접근성의 목적별 경로 제공
- 실제 앱 기능 화면과 경로 중심 시각 언어 사용
- 실증 수치를 팀 제공 PoC 결과로 명시하고 방법상 제한 공개
- 기관 관계를 PoC, 관심·검토, 지원, 협의, 육성 맥락으로 구분
- 짧은 문의 입력을 이메일 앱으로 넘기되 전송 성공을 가장하지 않음
- 자체 글꼴, 최적화 이미지, 작은 스크립트로 성능 개선
- 자동 링크·자산·메타·제목·대체 설명 검사 추가

## 최종 구조

```text
website/
├─ index.html
├─ product/index.html
├─ solutions/index.html
├─ technology/index.html
├─ proof/index.html
├─ company/index.html
├─ contact/index.html
├─ privacy/index.html
├─ accessibility/index.html
├─ styles/{tokens,base,components,pages}.css
├─ scripts/site.js
├─ assets/{fonts-web,media,product}/
├─ tests/check-site.mjs
├─ docs/
├─ package.json
├─ robots.txt
└─ sitemap.xml
```

정적 HTML을 유지해 프레임워크 자바스크립트와 서버 상태를 제거함. 콘텐츠는 스크립트 없이 모두 읽을 수 있고, 스크립트는 모바일 메뉴·현재 연도·문의 이메일 작성 보조에만 사용함.

## 디자인

- 핵심 모티프: 출발점, 경로, 분기점, 목적지
- 색상: Iruvy 보라색, 깊은 검정, 따뜻한 흰색
- 글꼴: 자체 제공 Pretendard 400·600·800
- 큰 편집형 한글 제목과 넓은 여백
- 제품 장면 외 카드 남용과 장식적 움직임 억제
- 모바일에서 한 단 중심으로 재배치

## 콘텐츠와 근거

핵심 문구는 `복잡한 실내에서도, 목적지까지 스스로.`임. 홈페이지는 사용자 가치 → 검증 → 문제 → 제품 경험 → 장점 → 도입 → 솔루션 → 기술 → 비전 → 문의 순서임.

한양대학교 학생회관 약 300m 이동 과제, 시각장애인 참여자 23명, 자력 도착률 26.6%에서 93.3% 변화는 팀 제공 PoC 결과로 표기함. 다른 시설에 일반화하거나 제삼자 인증으로 해석할 수 없다는 제한을 함께 공개함.

## 공개 경로

- `/`: 기관 구매자 중심 홈페이지
- `/product/`: 사용자 앱과 운영자 흐름
- `/solutions/`: 공공·복지, 병원·대학, 전시·복합시설
- `/technology/`: 신호, 위치 판단, 경로, 안내 구조
- `/proof/`: PoC 결과, 방법, 제한, 관계 구분
- `/company/`: 문제 관점, 팀 역할, 비전
- `/contact/`: PoC 문의와 후속 흐름
- `/privacy/`: 개인정보 처리 원칙
- `/accessibility/`: 접근성 목표와 제한

## 접근성

- 한국어 문서 언어, 본문 건너뛰기, 제목과 랜드마크
- 키보드 모바일 메뉴, 열림 상태, Escape 닫기
- 명확한 초점 표시와 움직임 축소
- 문의 레이블, 필수 검증, 실시간 상태 문구
- 이미지 대체 설명과 동일 정보의 주변 본문
- 주요 색상 대비 4.88:1 이상
- 390px에서 주요 경로 가로 넘침 없음

## 성능

- 홈페이지 HTML 약 17KB
- 전체 CSS 약 20KB
- 공용 스크립트 약 2.9KB
- 글꼴 세 파일 합계 약 156KB
- 첫 화면 장면 약 280KB
- 제품 화면은 홈페이지에서 지연 로드
- 외부 글꼴 요청과 실행 의존성 없음

운영 서버의 압축과 캐시 정책, 실제 핵심 웹 지표는 배포 후 확인 필요함.

## 알려진 제한

- 실증 원자료의 공개 링크는 아직 없음
- 현재 Iruvy 이름이 보이는 전체 최신 앱 캡처 묶음이 없음
- 문의 전송 서비스가 없어 사용자의 이메일 앱을 이용함
- 실제 화면 읽기 소프트웨어와 운영 서버 기반 성능 측정은 배포 후 추가 확인 필요

## 운영 배포

- 배포 주소: `https://iruvy.com/`
- 서버: SSH `atmos-prod`
- Caddy 문서 루트: `/var/www/riav`
- 이전 운영본 백업: `/var/www/iruvy-backups/riav-20260710-232341`
- 방식: 최소 운영 파일만 준비 디렉터리에 전송한 뒤 홈페이지와 API 상태 검사를 포함한 원자 교체
- Caddy API 분기(`/v1`, `/health`, `/docs`)는 변경하지 않음
- 외부 HTTPS에서 9개 공개 경로와 사이트맵·로봇 설정 모두 200 응답 확인
- 운영 홈페이지와 공유 이미지 해시가 로컬 검증본과 일치함을 확인
- 공개 HTML 경로는 배포 전 문서가 남지 않도록 `Cache-Control: no-cache, no-store, must-revalidate` 적용
- CSS, 이미지 등 정적 자산에는 HTML 전용 캐시 정책을 적용하지 않음

## 다음 운영 반영 절차

1. 릴리스 후보에서 `npm run build` 재실행
2. 현재 `/var/www/riav`를 시간 표시 백업 디렉터리로 이동
3. 준비 디렉터리를 `/var/www/riav`로 원자 교체
4. `/`, `/product/`, `/proof/`, `/contact/`, `/privacy/`, `/sitemap.xml`, `/health` 응답 확인
5. 실패 시 새 문서 루트를 분리하고 직전 백업을 즉시 복원
6. 데스크톱과 모바일에서 첫 화면, 메뉴, 문의 검증
