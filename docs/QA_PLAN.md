# QA Plan

대상: 9페이지 정적 사이트(히어로 재설계 후). 자동 도구만 신뢰하지 않고 수동 병행(§14).

## 기능 QA
네비(헤더/모바일 토글·Esc·포커스 복귀), 탭 위젯(화살표·Home/End·aria-selected), 링크·앵커(#service 등), 문의 폼(라벨·검증·mailto·aria-live), 리다이렉트 스텁.

## 콘텐츠 QA
맞춤법·수치 일관(96.7%/90명, 구 93.3%/23명 잔존 0), 브랜드(Riav/Atmos 노출 0), 관계 표현 정직, CTA 라벨 통일("PoC 문의하기"), alt·캡션, title/og 정합.

## 시각 QA
데스크톱/태블릿/모바일, 라이트 히어로↔흰 섹션 전환, 폰 목업 클리핑·오버랩, 긴/짧은 텍스트, 200% 확대, 가로 오버플로우 0, 하위 페이지 톤.

## 접근성 QA
대비(라이트 히어로 재확인), 키보드 전 경로, 초점 순서·가시성, 제목 순서, 타깃 크기 24×24(2.5.8), 모션 축소, 스크린리더 1패스.

## 성능 QA
폰트 프리로드·swap, 이미지 width/height·lazy, 대용량 미디어 배포 제외, 불필요 스크립트 없음.

## 링크·빌드 QA
`node tests/check-site.mjs`(링크·자산·메타·제목·alt), `node -c scripts/site.js`, 내부 링크·앵커 유효.

## 회귀 QA
히어로 재설계가 다른 8페이지·CSS(공유 토큰·버튼)·JS에 준 영향, 죽은 클래스/JS 제거 여파.
