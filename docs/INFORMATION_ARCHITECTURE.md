# Information Architecture

원칙: 내부 부서가 아니라 **챔피언의 의사결정 흐름**을 따라 구성(§8). 벤치마크 함의: 대상/섹터 우선 네비 + 별도 근거 레이어 + 상시 CTA + 조달 지원물.

## 현행 사이트맵 (9경로)

```
/            홈 (챔피언 무장)
/product/    제품(Iruvy Go 사용자·운영자 경험)
/solutions/  솔루션(시설별 도입 이유·지표)
/technology/ 기술(신호 위계·단계 도입·프라이버시)
/proof/      실증(수치·방법·제한·관계 구분)
/company/    회사·비전(장기 서사는 여기로 한정)
/contact/    문의(무료/Light PoC)
/privacy/    개인정보 처리방침
/accessibility/ 웹 접근성 선언
```
+ `privacy.html`·`support.html` 리다이렉트 스텁, `robots.txt`, `sitemap.xml`.

## 네비게이션

- 헤더: 제품·솔루션·기술·실증·회사 + CTA(PoC 문의) — 전 페이지 일관(2026-07-11 통일).
- 푸터: 살펴보기(제품·솔루션·기술·실증·회사) + 연락·정책(문의·이메일·개인정보·접근성).

## 홈 의사결정 흐름 (챔피언 기준 권장 순서)

리서치 종합 권장(§22.4 각색 — 대표 히어로 결정과의 관계는 DECISIONS D-HERO):

1. 히어로: 즉시 이해(실제 목적지까지 안내 인프라) — *현행은 감정 슬로건+앱 목업; 구매자-결과 리드로 강화 검토*
2. 강한 결과 지표(26.6%→96.7%, 제한 명시)
3. 접근성 문제(입구까지 vs 실제 목적지)
4. 작동 방식(사용자·운영자·기관 흐름)
5. 시설별 도입 이유·지표(솔루션)
6. 기관이 얻는 것(민원 감소·근거 리포트·의무 지원)
7. 실명 레퍼런스(관계 유형 정직)
8. 도입 단계·부담(무료 SW→장치)
9. 프라이버시·조달 경로(veto 대응)
10. 조달 킷 다운로드 + 무료/Light PoC CTA
11. 감정 한 줄(마무리)

## 미응답 반대 → 배치 지도

| 반대 | 페이지/섹션 |
|---|---|
| 프라이버시 | 기술·개인정보 |
| 설치·유지 | 기술(단계 도입)·솔루션·제품(운영자) |
| 레퍼런스 | 홈·실증(관계 구분) |
| ROI·예산 | 홈·솔루션 |
| 조달 경로 | 홈/솔루션(조달청 혁신제품) — *추가 검토* |
| 회사 존속성 | 회사 |

## 갭 (후속)

- 조달청 혁신제품·무과실 경로 안내 콘텐츠 부재 → 추가 검토.
- 다운로드형 조달 킷(원페이지·PoC 제안서)의 웹 게시 연결(파일은 `deliverables/` 존재).
