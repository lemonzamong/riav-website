# Iruvy 웹사이트 디자인 벤치마크와 적용 원칙

- 기준일: 2026-07-13
- 목적: 미적 완성도, 유사 사업 구조, 병원 구매와 실내 접근성 관점의 레퍼런스를 결합하되 특정 사이트를 복제하지 않는다.

## 조사군

### 미적 완성도와 제품 표현

- Linear: 절제된 정보 밀도, 하나의 주장에 집중하는 히어로, 제품 화면 중심 전개
- Stripe: 복잡한 제품군을 고객 문제와 실제 UI 예시로 설명하는 방식
- Vercel: 흑백 기반 타이포그래피, 빠른 시각 위계, 기술 신뢰를 만드는 세부 표현
- Resend: 짧은 문장, 넓은 여백, 개발자 제품의 명료한 전환 구조

### 현실·공간·운영 데이터

- Samsara: Physical Operations라는 상위 범주와 산업별 구매 언어
- Protex AI: 기존 인프라를 운영 인텔리전스로 전환하는 메시지와 현장 데이터 시각화
- Celonis: Measure–Understand–Act 구조와 결과 중심 프로세스 인텔리전스
- Kontakt.io: 병원 RTLS, 자산·환자·직원 흐름을 구매 문제별로 구분하는 방식

### 병원 운영

- Qventus: 병원 문제, 운영 결과, 제품 행동과 고객 사례의 연결
- Laudio: 간호 리더·CNO·COO 등 구매자별 언어와 현장 부담을 다루는 어조
- LeanTaaS: 병원 운영 지표와 구체적인 적용 영역의 연결

### 실내 접근성·내비게이션

- Waymap: 사용자 여정과 시설 구매 모델의 분리
- GoodMaps: 접근성을 제품 정체성으로 증명하는 방식
- Pointr: 지도·위치·경로 기술을 실제 제품 UI로 보여주는 방식
- Mappedin: 적용 공간별 사용 장면과 사전·현장·모바일 접점의 연결

## 채택한 원칙

1. 홈페이지는 회사 정의, 제품 선택, 공통 기술만 설명한다.
2. Flow와 Go에서 회사 비전 문장을 반복하지 않는다.
3. 기본 테마는 밝고 중립적으로 유지하며 다크 모드는 사용자 선택으로 제공한다.
4. 장식용 카드보다 실제 제품 화면, 데이터 상태와 사용자 행동을 보여준다.
5. 한 화면에 하나의 주장만 둔다.
6. 근거가 없는 고객 로고, 성과 수치와 인증 배지를 만들지 않는다.
7. Flow는 사람 평가가 아니라 병동 운영 변화의 순환을 보여준다.
8. Go는 기술보다 목적지 선택–이동 안내–도착이라는 경험을 먼저 보여준다.
9. 제품별 CTA는 각각의 문의 유형으로 바로 연결한다.
10. 모바일과 키보드 사용, 색 대비와 움직임 축소 설정을 디자인과 동등한 품질 기준으로 둔다.

## 이후 품질 향상 조건

- Flow 실제 현장 실증이 시작되면 개념 화면을 익명화된 실제 산출물 구조로 교체한다.
- Go 실증 원자료와 공개 동의가 확보되면 실증 페이지에 방법론과 기관별 사례를 추가한다.
- 고객 로고와 인용문은 공개 권한과 증빙 확인 후에만 사용한다.
- 제품 화면이 변경될 때 마케팅용 목업도 같은 릴리스에서 갱신한다.
