# 정보 구조

## 탐색 원칙

첫 화면은 기관 담당자에게 맞추고, 기술과 장기 비전은 더 깊은 경로에서 설명함. 메뉴는 다섯 개로 제한하고 도입 문의를 한 가지 주요 행동으로 통일함.

## 주요 메뉴와 경로

| 메뉴 | 경로 | 방문자 질문 |
|---|---|---|
| 제품 | `/product/` | 사용자는 실제로 어떻게 길을 찾는가 |
| 솔루션 | `/solutions/` | 우리 시설에는 어떤 방식으로 적용되는가 |
| 기술 | `/technology/` | 어떤 신호와 구조로 동작하는가 |
| 실증 | `/proof/` | 어떤 조건에서 무엇이 검증되었는가 |
| 회사 | `/company/` | 누가 왜 이 문제를 해결하는가 |
| 주요 행동 | `/contact/` | PoC를 어떻게 시작하는가 |

보조 경로는 `/privacy/`, `/accessibility/`로 구성함. 기존 `/privacy.html`, `/support.html`은 호환 링크 또는 이전 안내를 유지함.

## 홈페이지 설득 순서

1. 제품을 바로 설명하는 첫 화면
2. 검증 수치와 근거 상태
3. 건물 입구 이후의 마지막 실내 이동 문제
4. 사용자 앱과 운영자 도구의 실제 경험
5. 빠른 시작, 접근성, 운영 가능성, 단계적 정밀화
6. PoC 도입 과정
7. 시설 문제별 솔루션
8. 한양대학교 학생회관 사용자 PoC 맥락
9. 입력 → 위치 판단 → 경로 → 안내 구조
10. 사람의 이동에서 더 지능적인 공간으로 이어지는 비전
11. PoC 문의

## 전환 흐름

`첫 화면 주요 행동 → 문의 페이지 → 6개 이하 필수 항목 → 이메일 작성 또는 연결된 전송 서비스`

외부 전송 기반이 확인되기 전에는 브라우저 안에서 성공 상태를 가장하지 않고, 입력값을 사용자의 이메일 작성 화면으로 넘기는 방식만 사용함.
